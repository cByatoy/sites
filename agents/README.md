# Команда агентов: как всё настроить

6 чатов (облачные сессии Claude Code) работают над одним проектом. **Главный — Координатор**: пять исполнителей общаются только через него.

| Чат | Название сессии | Файл роли |
|---|---|---|
| Координатор | `Студия · Координатор` | `agents/00-coordinator.md` |
| Общение с клиентами | `Студия · Клиенты` | `agents/01-clients.md` + `agents/shared/client-intake-checklist.md` |
| Поиск клиентов | `Студия · Поиск` | `agents/02-leads.md` |
| Сайты и портфолио | `Студия · Сайты` | `agents/03-sites.md` |
| Документы | `Студия · Документы` | `agents/04-documents.md` |
| Проверка сайтов (QA) | `Студия · Проверка` | `agents/05-qa.md` |

Общие правила для всех — `agents/shared/rules.md`, схема работы — `agents/shared/workflow.md`.

---

## Шаг 1. Сохрани данные из старого чата
Временная папка старой сессии пропадёт. Скачай из чата и сохрани у себя:
- `barbershops-spb-full.xlsx` — таблица всех клиентов и статусов;
- `messages-barbershops-01…04.md` — отправленные волны;
- `meeting-the-mustache.md` — шпаргалка;
- файлы Kwork (обложки, портфолио, тексты).

## Шаг 2. Общая закрытая память — CRM
Чаты не видят друг друга, поэтому данные клиентов хранятся в одном закрытом месте:
**Claude Docs → документ «Студия — CRM»** (коннектор Claude Docs уже есть в твоём аккаунте).
В нём: таблица клиентов (название, адрес, канал, статус, дата, следующий шаг), раздел на каждого «живого» клиента (переписка кратко, бриф, цена), очередь лидов.

> Создать CRM можно попросить любой из чатов: «Создай документ Студия — CRM и перенеси туда таблицу из файла» (приложи xlsx).

**В публичный репозиторий данные клиентов не кладём никогда.**

## Шаг 3. Создай 6 сессий
На **claude.ai/code** (с компьютера удобнее):
1. «Новая сессия» → репозиторий **cByatoy/sites** → окружение то же, что сейчас (с полным доступом к сети).
2. Переименуй сессию по таблице выше (меню сессии → Rename).
3. Первым сообщением отправь текст из шага 4 для этой роли.
4. Повтори для всех шести. Сначала создай пятерых исполнителей, Координатора — последним (чтобы он сразу нашёл остальных).

## Шаг 4. Первые сообщения

**Координатор**
```
Ты — Координатор студии. Прочитай agents/00-coordinator.md и всё из agents/shared/. Найди через list_sessions сессии «Студия · Клиенты», «Студия · Поиск», «Студия · Сайты», «Студия · Документы», «Студия · Проверка» и запомни их id. Отправь каждой короткое сообщение со своим session id, чтобы они знали, кому отвечать. Затем открой CRM в Claude Docs («Студия — CRM») и дай сводку: кому напомнить, кто ждёт ответа, что в работе.
```

**Клиенты**
```
Ты — агент «Клиенты». Прочитай agents/01-clients.md, agents/shared/rules.md и agents/shared/client-intake-checklist.md. Я буду присылать скриншоты переписки с клиентами — готовь мне ответы, считай цены, собирай бриф по чек-листу и отмечай всё в CRM (Claude Docs «Студия — CRM»). Задачи для «Сайтов» передавай через Координатора.
```

**Поиск**
```
Ты — агент «Поиск». Прочитай agents/02-leads.md и agents/shared/rules.md. Сверься с CRM (Claude Docs «Студия — CRM»), кому уже писали, и подготовь волну на 10 барбершопов на сегодня.
```

**Сайты**
```
Ты — агент «Сайты». Прочитай agents/03-sites.md и agents/shared/rules.md, посмотри concepts/ и demos/. Жди задачи от Координатора; первое — проверь, что концепты и портфолио открываются на cbyatoy.github.io.
```

**Документы**
```
Ты — агент «Документы». Прочитай agents/04-documents.md, agents/shared/rules.md и business/documents/README.md. Жди задач от Координатора: договоры, акты, КП, политика ПД. Документы с реквизитами — только мне файлом и в CRM, не в репозиторий.
```

**Проверка**
```
Ты — агент «Проверка» (QA). Прочитай agents/05-qa.md и agents/shared/rules.md. Первая задача: прогони чек-лист по концептам concepts/barbers-time и concepts/the-mustache на cbyatoy.github.io (iPhone, Android, планшет, десктоп, доступность из России) и пришли отчёт Координатору.
```

## Шаг 5. Коннекторы и файлы по чатам

| Чат | Репозиторий | Коннекторы | Что прикладывать |
|---|---|---|---|
| Координатор | cByatoy/sites | **Claude Docs** (CRM) | ничего, работает с CRM |
| Клиенты | cByatoy/sites | **Claude Docs** (CRM) | скриншоты переписки, присланные клиентом файлы, реквизиты |
| Поиск | cByatoy/sites | **Claude Docs** (CRM) | ничего; нужен полный доступ к сети (уже есть) |
| Сайты | cByatoy/sites | **Claude Docs** (CRM, бриф) | логотипы, фото, визитки клиента |
| Документы | cByatoy/sites | **Claude Docs** (CRM, реквизиты) | реквизиты клиента (ИП/ООО, ИНН), подписанные сканы |
| Проверка | cByatoy/sites | **Claude Docs** (CRM — чтобы сверять телефоны, цены, адреса) | ничего; нужен полный доступ к сети (уже есть) |

- **GitHub** подключён ко всем через репозиторий `sites` — так все видят одни и те же инструкции, концепты и шаблоны.
- **Netlify** больше не нужен: публикуем через GitHub Pages (Netlify в России не открывается без VPN).
- WhatsApp/Telegram подключить к агентам нельзя — сообщения клиентам всегда отправляешь ты.

## Шаг 6. Как Координатор передаёт работу
В облачных сессиях есть инструменты `list_sessions` и `send_message`: Координатор сам отправляет задачу нужному агенту, тот выполняет и отвечает Координатору. Файлы передаются через репозиторий (код, концепты) и CRM (данные клиентов), в сообщении — что сделать и где лежит.
Если агент не отвечает (сессия уснула) — открой его чат и напиши «проверь входящие задачи от Координатора».

## Твой день (≈ 15 минут)
1. **Координатору:** «сводка» → получаешь план.
2. **Поиску:** волна на сегодня → отправляешь 10 сообщений → пишешь Поиску, кому ушло.
3. **Ответы клиентов** → скриншот в чат «Клиенты» → копируешь готовый ответ.
4. **Готовые концепты/сайты** приходят от Координатора уже с отчётом «Проверки» → смотришь на своём телефоне → отправляешь клиенту.
5. **Документы** (договор, акт) приходят файлом от Координатора → проверяешь, отправляешь клиенту, загружаешь подписанный скан обратно.

## Если что-то сломалось
- GitHub Pages завис («in progress deployment») — Settings → Pages → Source: None → Save → обратно `main` / `root`.
- Чат «забыл» контекст — попроси его заново прочитать свой файл роли и CRM.
